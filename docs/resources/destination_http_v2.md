# rudderstack_destination_http_v2 (Resource)

Configure HTTP v2 with a JSONata template over `$$.events`. Set `format` to JSON (default), XML, or FORM. XML and FORM templates must produce one object; XML wraps it in `xml_root_key` (default `root`), while FORM sends top-level keys as form fields. JSON and XML require `max_batch_size` (1–5,000); FORM always sends one event per request, so omit the batch size. The existing `rudderstack_destination_http` resource remains on version 1.

For more information, see https://www.rudderstack.com/docs/destinations/streaming-destinations/http/.

## Migrating an existing HTTP destination from v1

After the control plane migrates the destination to version 2, the old `rudderstack_destination_http` resource cannot refresh it: the provider rejects the version mismatch rather than writing v1 configuration over the migrated destination. Update your HCL to use `rudderstack_destination_http_v2` with the migrated JSONata `request_body_template` and the appropriate format and batch size. Back up your Terraform state, then move the existing ID between resource types without deleting the remote destination:

```shell
terraform state rm rudderstack_destination_http.example
terraform import rudderstack_destination_http_v2.example <destination-id>
terraform plan
```

Replace the example addresses and ID with yours (including module prefixes if applicable). Remove the v1 resource from HCL before planning: leaving it configured would create another destination. Do not use `terraform state mv` across the two resource types; import lets the v2 schema read the migrated configuration. Resolve any plan differences before applying.

## Example Usage

```terraform
resource "rudderstack_destination_http_v2" "example" {
  name = "my-http-jsonata-destination"

  config {
    api_url = "https://example.com/webhooks/events"

    auth          = "apiKeyAuth"
    api_key_name  = "x-api-key"
    api_key_value = "your-api-key"

    method = "POST"
    format = "JSON"

    request_body_template  = <<-JSONATA
      [$$.events.{"customer": {"id": userId}, "items": properties.items}]
    JSONATA
    supported_message_types = ["track", "identify"]

    max_batch_size = "5000"
  }
}
```

### XML and FORM examples

```terraform
resource "rudderstack_destination_http_v2" "xml" {
  name = "my-http-xml-destination"

  config {
    api_url      = "https://example.com/events.xml"
    format       = "XML"
    xml_root_key = "Events"

    request_body_template = <<-JSONATA
      {"event": $$.events.{"id": messageId}}
    JSONATA
    max_batch_size = "10"
  }
}

resource "rudderstack_destination_http_v2" "form" {
  name = "my-http-form-destination"

  config {
    api_url               = "https://example.com/form"
    format                = "FORM"
    request_body_template = <<-JSONATA
      {"email": $$.events[0].traits.email}
    JSONATA
  }
}
```
