# rudderstack_destination_deltalake (Resource)

This resource represents a Databricks (Delta Lake) destination. For more information check
https://www.rudderstack.com/docs/destinations/warehouse-destinations/deltalake/

## Example Usage

```terraform
resource "rudderstack_destination_deltalake" "example" {
  name = "my-deltalake"

  config {
    host = "abc-12345de-6789.cloud.databricks.com"
    port = "443"
    path = "/sql/1.0/endpoints/..."
    # Personal access token auth (default):
    token = "..."
    # Machine-to-machine OAuth auth instead of a token:
    # use_oauth = true
    # oauth_client_id = "..."
    # oauth_client_secret = "..."
    # catalog = "..."
    # namespace = "..."
    sync {
      frequency = "30"
      # start_at                  = "10:00"
      # exclude_window_start_time = "11:00"
      # exclude_window_end_time   = "12:00"
    }
    # skip_tracks_table = false
    # skip_users_table = true
    # prefer_append = true
    # Create the Delta tables outside the Databricks-managed location:
    # enable_external_location = true
    # external_location = "/mnt/example/delta"
    # Changing either of these replaces the destination:
    # underscore_divide_numbers = false
    # allow_users_context_traits = false

    # Staging object storage. Must match the staging block below.
    bucket_provider = "S3"
    # use_rudder_storage = true  # use RudderStack-managed buckets and omit the staging block
    # cleanup_object_storage_files = false
    # prefix = "..."
    # S3 with access keys:
    s3 {
      bucket_name    = "..."
      use_sts_tokens = true
      access_key_id  = "..."
      access_key     = "..."
      # enable_sse = true
    }
    # S3 with IAM role-based auth (conflicts with access_key_id/access_key):
    # s3 {
    #   bucket_name = "..."
    #   use_sts_tokens = true
    #   role_based_authentication {
    #     i_am_role_arn = "arn:aws:iam::123456789012:role/MyRole"
    #   }
    # }
    # gcs {
    #   bucket_name = "..."
    #   credentials = "..."
    # }
    # azure_blob {
    #   container_name = "..."
    #   account_name = "..."
    #   account_key = "..."
    #   # SAS token instead of the account key:
    #   # use_sas_tokens = true
    #   # sas_token = "..."
    #   # enable_hierarchical_namespace = false
    # }
    # connection_mode {
    #   web = "cloud"
    #   android = "cloud"
    #   android_kotlin = "cloud"
    #   ios = "cloud"
    #   ios_swift = "cloud"
    #   unity = "cloud"
    #   amp = "cloud"
    #   cloud = "cloud"
    #   cloud_source = "cloud"
    #   reactnative = "cloud"
    #   flutter = "cloud"
    #   cordova = "cloud"
    #   shopify = "cloud"
    # }
    # consent_management {
    # 	web = [
    # 		{
    # 			provider = "oneTrust"
    # 			consents = ["one_web", "two_web", "three_web"]
    # 			resolution_strategy = ""
    # 		},
    # 		{
    # 			provider = "custom"
    # 			resolution_strategy = "and"
    # 			consents = ["one_web", "two_web", "three_web"]
    # 		}
    # 	]
    # 	android = [{
    # 		provider = "ketch"
    # 		consents = ["one_android", "two_android", "three_android"]
    # 		resolution_strategy = ""
    # 	}]
    # 	ios = [{
    # 		provider = "custom"
    # 		resolution_strategy = "or"
    # 		consents = ["one_ios", "two_ios", "three_ios"]
    # 	}]
    # }
  }
}
```

> **:warning: Note**
>
> `bucket_provider` is required and has to match the staging block you declare: `s3` for `S3`, `gcs` for `GCS`, `azure_blob` for `AZURE_BLOB`. Set `use_rudder_storage` to true to stage data in RudderStack-managed buckets and leave all three blocks out; `bucket_provider` is still required by the control plane in that case.

> **:warning: Note**
>
> Changing either `allow_users_context_traits` or `underscore_divide_numbers` forces a new destination to be created. Both are one-time flags that distinguish older destination behaviour from newer, and the control plane rejects any update to them, so an in-place change could never succeed. Terraform replaces the destination instead — which assigns a **new destination ID**, so any connection pointing at it has to be re-pointed, and the warehouse will receive a different column set from the one it already holds. Plan carefully before changing either value on an existing destination.

- `path` (String) HTTP path of your Databricks SQL warehouse. For example, `/sql/1.0/endpoints/<endpointId>`.

- `external_location` (String) Path of the external location for the Delta tables. Applies only to tables RudderStack creates after the change; existing tables are left as they are.

- `prefer_append` (Boolean) Enable append operation for warehouse syncs. Disable to use merge, which rules out duplicate rows but makes syncs considerably slower.
- `prefix` (String) If specified, RudderStack will create a folder in the bucket with this prefix and push all the data within that folder.
- `s3` (Block List, Max: 1) S3 staging settings. Declare this block when `bucket_provider` is `S3` and `use_rudder_storage` is false. (see [below for nested schema](#nestedblock--config--s3))
- `skip_tracks_table` (Boolean) Enable this toggle to skip sending the event data to the tracks table.
- `skip_users_table` (Boolean) Disable the creation of a users table.
- `token` (String, Sensitive) Databricks personal access token. Required when `use_oauth` is false.
- `underscore_divide_numbers` (Boolean) Use underscores to split numeric segments in column names. Changing this forces a new destination to be created, because the control plane treats the field as immutable.
- `use_oauth` (Boolean) Authenticate with a Databricks machine-to-machine OAuth service principal instead of a personal access token. Set `oauth_client_id` and `oauth_client_secret` when enabled.
- `use_rudder_storage` (Boolean) Enable this setting to use RudderStack-managed buckets for object storage. Only available on RudderStack-hosted data planes.
